# Легенды Асура — онлайн-версия

Онлайн-игра «Легенды Асура»: Python-сервер (чистый stdlib, без внешних зависимостей) + адаптированный веб-клиент.

**Что умеет:**
- Общие аккаунты и синхронизация прогресса между устройствами.
- Чат (WebSocket), таблица лидеров.
- PvP-бой 1-на-1 в реальном времени (очередь, ходы, награда победителю).

Без `pip install`. Нужен только Python 3.8+ (используется на любом хостинге).

---

## Структура

```
asura-online/
├── server.py       # HTTP (REST) + WebSocket сервер
├── index.html      # игровой клиент (сам раздаётся сервером)
├── asura_data.json # база аккаунтов и сохранений (создаётся автоматически)
└── README.md
```

## Локальный запуск

```bash
python server.py
```

Открыть: `http://127.0.0.1:8080/`

Порт по умолчанию `8080`, меняется переменной окружения `PORT`:

```bash
PORT=9000 python server.py     # Linux/macOS
set PORT=9000 && python server.py   # Windows (cmd)
```

### Тестовые учётки
- Владелец: ник **Santa Tedis**, пароль **santaOwner777** → роль `owner` 👑 (зашит отдельно в `_login`).
- Обычный игрок: зарегистрируйте свой ник в клиенте (роль `player`).

## Установка как приложение на телефон (PWA)

Игра — PWA: на телефоне её можно сохранить на главный экран с иконкой и запускать как обычное приложение, в отдельном окне, без браузерной строки.

> Важно: установка работает с **публичной HTTPS-ссылки** (после хостинга). С `http://127.0.0.1:8080` браузер телефона не сможет открыть сайт — по этой ссылке игра доступна только на этом компьютере.

Как установить на телефон (после того как есть публичная ссылка):

**Android (Chrome), обычно так:**
1. Откройте ссылку игры в Chrome.
2. Нажмите меню (⋮) → **«Добавить на главный экран»** (или «Установить приложение»).
3. Подтвердите — появится иконка «Асура» на домашнем экране.

**iPhone/iPad (Safari):**
1. Откройте ссылку в Safari.
2. Нажмите кнопку **Поделиться** (квадрат со стрелкой вверх).
3. Выберите **«На экран “Домой”»**.
4. Подтвердите — иконка появится на главном экране.

**Что получается:**
- Иконка со своим названием («Асура»), запуск на весь экран, без адресной строки.
- Игра работает как обычно: вход в аккаунт, прогресс, чат, лидеры и PvP.
- Каждый игрок на телефоне заходит под своим ником — прогресс у него свой.

Файлы PWA (для проверки/хостинга): `manifest.json`, `icon-512.png`, `icon-192.png`, `icon-180.png`. Сервер отдаёт их с правильными `Content-Type` (`application/json`, `image/png`) — правки для этого уже в `_serve_static`.

## Развертывание на хостинге

Сервер слушает `0.0.0.0` и читает порт из переменной окружения `PORT` — стандарт для большинства PaaS. Клиент сам берёт адрес сервера из `location.origin` (index.html:344), WebSocket строится от того же origin (index.html:514), поэтому **правки кода при хостинге не нужны**.

### Вариант А — Render (рекомендуется для Python + WebSocket)
1. Зарегистрируйтесь на render.com.
2. **New → Web Service**, подключите GitHub-репозиторий с папкой `asura-online`.
3. Настройки:
   - **Root Directory**: `asura-online`
   - **Build Command**: `true` (зависимостей нет)
   - **Start Command**: `python server.py`
   - **Instance Type**: Free
4. **Deploy**. Откройте выданный URL — игра доступна из интернета.

### Вариант Б — Railway
1. railway.com → New Project → Deploy from GitHub (та же папка).
2. Start command: `python server.py`.
3. Откройте `https://<название>.up.railway.app`.

### Вариант В — Replit (быстрый прототип без GitHub)
1. replit.com → Create Repl → **Python**.
2. Загрузите `server.py` и `index.html`.
3. В закладке **Secrets** добавьте `PORT=8080`.
4. **Run** — Replit выдаст URL в панели Webview.

## Постоянство данных (важно!)

- База хранится в файле `asura_data.json` рядом с `server.py`.
- На Render/Railway/Replit файловая система **эфемерна:** при перезапуске/деплое файл может сбрасываться.
- Чтобы прогресс игроков переживал рестарты, подключите **облачный сторонний бэкап** (см. ниже).

---

## Настройка облачного хранилища (JSONBin)

Сервер умеет подстраховывать локальный файл в [JSONBin.io](https://jsonbin.io) — хранилище JSON без сервера и карты (бесплатный тариф для прототипа).

Как это работает:
- При старте, если локальный файл пуст — сервер тянет базу из облака.
- Каждая запись (`/api/save`, регистрация, награда за бой) — после записи в файл пушится в облако в фоновом потоке.
- Облако **best-effort**: если ключей нет или JSONBin недоступен, игра продолжает работать локально, ничего не ломается и не блокируется.

### Как получить ключи
1. Зарегистрируйтесь на jsonbin.io, создайте коллекцию/бин (Bin).
2. Запомните:
   - **Bin ID** — идентификатор бина (часть URL, `.../v3/b/<ID>`).
   - **X-Master-Key** — мастер-ключ из раздела API Keys.

### Задать на локальной машине
```bash
# Linux/macOS
BIN_ID=<BinId> BIN_KEY=<MasterKey> python server.py

# Windows (cmd)
set BIN_ID=<BinId>
set BIN_KEY=<MasterKey>
python server.py
```

### Задать на Render/Railway
В панели сервиса добавьте **Environment Variables**:
- `BIN_ID` = ваш Bin ID
- `BIN_KEY` = ваш X-Master-Key

(На Railway — раздел **Variables**; на Replit — закладка **Secrets**.)

После этого облако станет основой персистентности, а локальный файл — кэшем.

## API (кратко)

| Метод | Путь | Тело / параметры | Ответ |
|-------|------|------------------|-------|
| POST | `/api/register` | `{nick, pass}` | `{token, nick, role}` |
| POST | `/api/login` | `{nick, pass}` | `{token, nick, role}` |
| GET | `/api/load?token=...` | — | `{state, nick, role}` |
| PUT | `/api/save` | header `Authorization: Bearer <token>`, `{state}` | `{ok}` |
| GET | `/api/leaderboard` | — | топ 50 |
| WS | `/ws?nick=...` | — | чат (type `chat`) и PvP (типы `fight_*`) |

## Ограничения прототипа

- Бой в памяти сервера: текущая сессия PvP сбрасывается при рестарте сервера (очередь и активные бои не переживают перезапуск).
- Одиночный процесс без БД: для продакшена вместо JSONBin лучше использовать настоящую БД (Postgres/Supabase).
- Конкурентные записи: спам в бою/сохранении упрощён, без транзакций БД.
